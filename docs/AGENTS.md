# AGENTS.md

Este documento define la guía de colaboración obligatoria para cualquier agente de Inteligencia Artificial que trabaje en este repositorio.

## Descripción del proyecto

El proyecto comenzó como una invitación digital de casamiento para Marcela y Jorge, y evolucionará hacia una plataforma colaborativa y emocional llamada **Centro de Recuerdos**, manteniendo el mismo enlace original antes y después de la celebración.

## Tecnologías

- HTML
- CSS Vanilla
- JavaScript Vanilla
- Firebase (Firestore, Storage, Security Rules)
- Netlify

## Tecnologías prohibidas

- Bootstrap
- Tailwind
- React
- Vue
- Angular
- Cualquier otro Framework CSS
- Cualquier otro Framework JavaScript

## Documentación obligatoria

Antes de analizar, proponer o modificar cualquier línea de código, es estrictamente obligatorio leer los siguientes documentos:

- `docs/PRODUCT_VISION.md`
- `docs/DEVELOPMENT_RULES.md`
- `docs/ARCHITECTURE.md`

## Filosofía

- **Mantener la estética existente:** Conservar la línea visual, elegante y emocional del diseño actual.
- **No romper la experiencia actual:** Asegurar la estabilidad de las características ya implementadas.
- **Cambios pequeños e incrementales:** Evitar modificaciones o refactorizaciones masivas no solicitadas.
- **Una historia de usuario por vez:** Resolver tareas de manera enfocada, aislada y secuencial.
- **Mantener compatibilidad con Netlify:** Respetar los estándares de despliegue estático.
- **Mobile First:** Priorizar siempre la visualización y experiencia en dispositivos móviles.

## Forma de trabajo

### Antes de modificar código:
1. **Analizar:** Comprender el contexto y los archivos afectados.
2. **Explicar el plan:** Presentar detalladamente al usuario el enfoque técnico propuesto.
3. **Esperar aprobación:** No realizar modificaciones hasta recibir la confirmación explícita del usuario.

### Después de modificar código:
1. **Resumir cambios:** Explicar qué se hizo y la justificación del cambio.
2. **Indicar archivos modificados:** Listar con precisión cada archivo que sufrió alteraciones.
3. **Indicar cómo probar:** Proveer un paso a paso claro para validar y verificar la correcta funcionalidad del cambio.
